## colebrokamp.com

drive with [just](https://github.com/casey/just?tab=readme-ov-file#shell)

## build

The site is generated by a small Rust binary, MiniJinja templates, and `just`
as the command interface. Long-form articles use the same build and live with
the rest of the site content:

- `just build` renders the website, writing, CV, and RIS file.
- `just render` renders everything.
- `just render site` renders the root website and writing collection.
- `just render writing` renders only `_site/writing/`.
- `just render cv` renders `_site/peds-cv-brokamp.docx`.
- `just render ris` renders `_site/colebrokamp.ris`.
- `just preview` renders, serves `_site/`, and opens <http://localhost:8000>.

Generated output lives in `_site/` and is ignored by git. GitHub Actions builds
the repository and uploads a `site-preview` artifact on pull requests. When
`master` is updated, the same workflow deploys `_site/` to GitHub Pages.

The source layout is intentionally small:

- `content/*.md` is plain Markdown prose.
- `content/*.md.j2` is Markdown plus MiniJinja loops for YAML-backed sections.
- `content/writing/<slug>/index.md` is an article; other files in its folder are
  local assets.
- `templates/page.html.j2` is the shared HTML shell.
- `templates/writing/*.html.j2` contains the writing index and article bodies.
- `site.css` contains the site styling, including the small navbar rules that
  replace the old generated Bootstrap and Font Awesome assets.
- Root-level favicon files and `cole_circle.webp` are copied into the generated
  site; the custom domain is configured in GitHub Pages rather than a `CNAME`
  artifact.
- `data-raw/*.yaml` is list-shaped source data with no R-style top-level IDs.
- `data-raw/pubs.yaml` keeps display citations separate from explicit bibliographic fields
  such as `volume`, `number`, `pages`, and `note`.
- `src/*.rs` contains the Rust build code. See `src/README.md` for the module map.

`pulldown-cmark` converts website Markdown to HTML. Pandoc is still used only for
the Word CV output.

## publication export

`just render ris` generates `_site/colebrokamp.ris` from every entry in
`data-raw/pubs.yaml`; `just build` also generates it. The bibliography icon in
the site navigation links to this file, including from nested article pages.
The generated file is UTF-8 RIS and can be imported into reference managers or
NCBI My Bibliography using **Add citations → From a file**.
See [NCBI's upload instructions](https://www.nlm.nih.gov/pubs/techbull/ma19/ma19_mybibliography_overview.html).

Authors retain their source spelling and order, with one author per RIS field.
Optional metadata is exported only when supplied; missing details are not
looked up or inferred from the display citation. Edit `data-raw/pubs.yaml` and
regenerate rather than editing the RIS file directly.

## writing

Each article folder name becomes its URL slug, must use lowercase kebab-case
(for example, `tree-based-machine-learning`), and must contain exactly one
Markdown file named `index.md`. The file starts with strict YAML front matter:

```yaml
---
title: "Article title"
description: "A short description for the index and page metadata."
date: "2026-07-15"
---
```

All three fields are required, unknown fields are rejected, and `date` must use
`YYYY-MM-DD`. The article body begins after the closing delimiter and does not
need an H1 because the title is rendered from front matter. Articles appear
newest first on `/writing/`, with folder-name order used to break date ties.
Local images and other non-Markdown assets are copied beside the rendered page.
Level-two headings automatically receive linkable fragment IDs and act as their
own fragment links; use `{#custom-id}` after a heading when a stable explicit ID
is preferred.
